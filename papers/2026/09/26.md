### 1. 双超图索引：为检索增强生成中的多跳推理架起知识孤岛之间的桥梁
| 属性 | 内容 |
|------|------|
| **英文标题** | Dual-Hypergraph Indexing: Bridging Knowledge Islands for Multi-Hop Reasoning in Retrieval-Augmented Generation |
| **分类** | 大模型推荐 |
| **评分** | 6.8/10 ⭐⭐⭐ |
| **作者** | Qi Sun, Xingliang Hou, Caibo Li et al. |
| **作者单位** | — |
| **arXiv** | [2609.28108](http://arxiv.org/abs/2609.28108v1) |
| **PDF** | [下载](https://arxiv.org/pdf/2609.28108v1) |

针对超图RAG中超边被孤立为事实断言、形成阻碍多跳因果推理的"知识孤岛"问题，提出双超图索引（DHI）分层表示框架。DHI将基础实体-关系事实超图（H_K）与深层洞察超图（H_D）通过双路径聚合算法耦合：一是基于5维拓扑画像与自适应阈值的重要性驱动枢纽聚合，捕捉空间语义簇；二是基于滑动窗口贪心探索的时间块链渐进聚合，追踪时序演化。在五个基准上取得最优性能，Mix多学科基准逻辑连贯性提升1.53，复杂医学病理推理任务达85.78%。


**核心贡献**：

- 提出双超图索引（DHI）分层框架，通过双路径聚合算法将离散事实超边升级为结构化分析洞察，突破超图RAG的"知识孤岛"瓶颈。

- 设计重要性驱动的枢纽聚合机制，基于5维拓扑画像与自适应阈值捕捉空间语义簇，实现高阶实体关联的有效整合。

- 提出时间块链渐进聚合方法，利用滑动窗口贪心探索追踪时序演化，支撑多跳因果推理与叙事合成。

- 在五个基准上达到SOTA，Mix多学科基准逻辑连贯性提升+1.53，复杂医学病理推理任务准确率达85.78%。



> 💡 该论文为超图RAG中的多跳推理提供了系统性的分层索引架构，在医学病理等复杂推理任务上验证了显著效果，对构建下一代知识密集型RAG系统具有重要参考价值。

> 💡 该工作展示了LLM智能体在工业推荐系统中自主驱动模型研究闭环的可行性，并提供了大规模离线与在线实验证据，对推荐系统自动化研究范式具有重要参考价值。

### 3. 从兴趣到语义ID：面向生成式推荐的检索锚定信用分配

| **分类** | 大模型推荐 |

| **作者** | Mengdan Zhu, Yufan Zhao, Yao Zhao et al. |

| **arXiv** | [2609.29983](http://arxiv.org/abs/2609.29983v1) |
| **PDF** | [下载](https://arxiv.org/pdf/2609.29983v1) |

针对生成式推荐中语义ID（SID）奖励稀疏、信用分配不清的问题，本文提出检索锚定的查询归因方法。将推理轨迹结构化为历史摘要、兴趣假设与最终SID，利用冻结检索器将每个兴趣假设作为目录查询独立验证，当任一查询在top-K内检索到目标时给予奖励，并通过逐查询命中指示将奖励定位到具体假设，实现跨度级信用分配。在三个Amazon Reviews数据集上取得一致的SID推荐提升；在Video Games上，oracle分析表明从生成兴趣中选择目标相关查询可同时提升召回与排序。


**核心贡献**：

- 提出检索锚定的查询归因机制，将稀疏的SID精确匹配奖励转化为可独立验证的兴趣假设级奖励，解决组内全错时零优势与同奖励同优势两类信用分配失效问题。

- 在三个Amazon Reviews数据集上实现一致的SID推荐性能提升，并在Video Games上通过oracle分析证明兴趣条件化SID解码可同时提升召回与排序。

- 实现跨度级信用分配：仅命中目标的兴趣假设获得正检索优势，检索通道不更新最终SID跨度，使共享SID奖励的rollout可获得差异化更新。



> 💡 该工作精准切中生成式推荐中稀疏SID奖励导致的信用分配瓶颈，用检索验证将奖励下沉到兴趣假设层面，方法简洁且实验验证充分，值得推荐系统与LLM推荐研究者精读。

### 4. OneTrans-V2：用单一Transformer统一工业推荐中的召回、粗排与精排
| 属性 | 内容 |
|------|------|
| **英文标题** | OneTrans-V2: Unifying Retrieval, Pre-rank, and Fine-rank with One Transformer in Industrial Recommender |
| **分类** | 召回与排序 |
| **评分** | 5.9/10 ⭐⭐ |
| **作者** | Hannan Cao, Jun Guo, Haolei Pei et al. |
| **作者单位** | — |
| **arXiv** | [2609.28589](http://arxiv.org/abs/2609.28589v1) |
| **PDF** | [下载](https://arxiv.org/pdf/2609.28589v1) |

针对工业推荐级联系统中召回、粗排、精排各自独立训练与部署导致用户序列重复编码、优化割裂的问题，本文提出OneTrans-V2，用单一Transformer统一整个级联。模型将用户行为序列一次性编码为共享上下文，保留各阶段候选特征与计算，通过联合训练实现精排到粗排的模型内知识蒸馏；采用稀疏MoE扩展共享骨干并以μP式参数化稳定训练；提出决策条件生成式召回（DCGR）以决策前缀引导单一生成过程承载多业务目标；并提出序列原生训练（SNT）围绕用户终身行为序列组织训练。系统全量部署后GMV提升9.74%，在同等硬件预算下吞吐量达原级联的3.2倍。


**核心贡献**：

- 用单一Transformer统一召回、粗排、精排三阶段，用户行为序列仅编码一次，全量部署后GMV提升9.74%

- 引入稀疏MoE与μP式参数化扩展共享骨干，在受限激活计算下提升容量并稳定训练

- 提出决策条件生成式召回（DCGR），以决策前缀条件化生成物品，使业务目标驱动单一生成过程

- 配套协同设计的服务栈在同等硬件预算下实现3.2倍于原级联的吞吐量



> 💡 该工作首次在工业级规模上以单一Transformer打通召回—粗排—精排全级联，并给出GMV+9.74%、吞吐3.2倍的实证，是推荐系统架构统一方向的重要进展。

### 5. 评估结论的可复现性如何？对LLM推断提示结构的自我审计
| 属性 | 内容 |
|------|------|
| **英文标题** | How Reproducible Are Evaluation Conclusions? A Self-Audit of LLM-Inferred Prompt Structure |
| **分类** | 大模型推荐 |
| **评分** | 5.7/10 ⭐⭐ |
| **作者** | Dipankar Sarkar |
| **作者单位** | — |
| **arXiv** | [2609.30074](http://arxiv.org/abs/2609.30074v1) |
| **PDF** | [下载](https://arxiv.org/pdf/2609.30074v1) |

本文以LLM提示结构推断为案例，审计小样本评估结论的可信度。实验覆盖5个模型家族、8个开源模型（8B至675B参数），禁用缓存并持久化293个原始中间表示。发现相同调用无法稳定恢复相同结构，节点集Jaccard均值为0.39至0.96，72%的提示-模型单元从未达到节点集完美匹配。联合聚类自助法显示仅排名底部稳定：最不可复现的两个模型在99%和86%的重采样中保持排名，中间四个仅27%-48%，顶部两个各68%。两种合理的合并规则改变8行中的4行并使总体结论移动7个百分点。四个端点十周内被撤回，研究无法复现。建议报告排名稳定性、逐单元溯源、敏感性比较、原始输出及测量日期。


**核心贡献**：

- 揭示LLM提示结构推断本身极不稳定：相同调用下节点集Jaccard仅0.39-0.96，72%的提示-模型单元从未完美匹配。

- 联合聚类自助法证明排名结论仅底部可靠：最差两个模型保持排名概率99%和86%，而中间四个仅27%-48%，顶部两个各68%。

- 两种合理的重复实验合并规则即可改变8行排名中的4行，并使研究总体结论移动7个百分点。

- 四个评估端点在测量后十周内被撤回，原研究已无法复现，凸显小样本LLM评估的时效脆弱性。



> 💡 该文以严谨的自我审计揭示了LLM评估排名远不如表面可信，并给出可操作的报告规范，对任何依赖LLM评估的研究者都具有警示与指导价值。

### 8. 视觉语言模型长文档问答流程的实证研究

| **分类** | 多模态推荐 |
| **评分** | 5.5/10 ⭐⭐ |
| **作者** | Kenan E. Ak, Jay Mohta, Gwang Gook Lee et al. |
| **作者单位** | — |
| **arXiv** | [2609.29933](http://arxiv.org/abs/2609.29933v1) |
| **PDF** | [下载](https://arxiv.org/pdf/2609.29933v1) |

本文系统研究了视觉语言模型（VLM）处理长文档问答时的三类关键设计选择：文档输入方式、检索器选择以及静态与智能体式流程。在MMLongBench-Doc和LongDocURL两个基准上，使用前沿API模型与开源权重VLM进行实验。发现智能体流程仅在回答模型足够大时才优于静态输入；检索模态（图像vs文本）比具体检索器更重要，图像Top-k检索最具token效率；不同最强流程在不同问题上各有优势，逐题最优的oracle选择可提升约13个百分点，但基于证据类型的路由几乎无法复现该增益。

- 六工具智能体流程仅在回答VLM足够大时才有收益：Qwen3.5-4B/9B下落后于静态输入，27B下持平，Sonnet 4.5下领先

- 检索模态比具体检索器更关键：最强图像检索器优于最强文本流程，且Top-k图像检索token消耗仅为全页输入的1/7至1/4

- 三个最强流程在不同问题上各有成功，逐题oracle选择比最佳单一流程提升约13个百分点，但证据类型路由几乎无法恢复该增益



> 💡 该研究通过严谨的实证对比揭示了VLM长文档问答中模型规模、检索模态与流程架构的交互规律，为多模态文档理解系统的工程选型提供了可操作的量化依据。
